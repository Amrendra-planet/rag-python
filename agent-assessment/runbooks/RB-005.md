# RB-005 — checkout-api rollback
Service: checkout-api
Procedure: safely roll back a previous version

Before rollback:
1. Confirm the affected deployment/version.
2. Check the deployment history.
3. Confirm that rollback is appropriate with the incident lead.
4. Capture current error rate and latency for comparison.

Rollback:
1. Identify the last known-good checkout-api release.
2. Roll back using the deployment system.
3. Monitor error rate, latency, CPU, and database connections.
4. Confirm recovery before closing the incident.

If the rollback does not restore service, stop and escalate rather than repeatedly changing versions.
