# RB-001 — checkout-api high CPU
Service: checkout-api
Failure mode: sustained high CPU

Symptoms:
- checkout-api CPU remains above 85% for several minutes.
- Request latency increases while CPU is saturated.

First checks:
1. Check CPU usage by pod/instance and identify whether the load is isolated or widespread.
2. Check recent deployments and traffic volume.
3. Inspect application metrics for unusually expensive checkout requests.
4. Review logs for repeated retry loops or unexpected request spikes.

Mitigation:
- If caused by a bad deployment, follow RB-005 for rollback.
- If traffic is unexpectedly high, coordinate with the on-call lead before scaling.
